# 前端审美偏好（Yue）

这份文件总结 Yue 对网页前端的审美偏好，来源是 Sun-Aware Garden Planner 2026-11-14 至 11-15 的整站重新设计（ADR-0073）。这一版是 Yue 明确满意的结果。

**怎么用：** 在新项目里，把这份文件放进仓库（例如 `docs/design-preferences.md`），并在 `CLAUDE.md` 或 `AGENTS.md` 里写一句："做任何前端视觉决定之前，先读 `docs/design-preferences.md`。"

第 1–13 节是可以通用的原则。具体色值来自植物主题项目；换成别的主题时，按第 14 节换"品牌色"，但保留结构和比例。

---

## 1. 一句话总结

**安静、中性、干净、留足呼吸感的工作界面 + 少量深色、有真实质感的品牌色带 + 一个只出现一两次的荧光强调色。** 质感（高清、有触感、像真实材料）比配色和谐更重要。整体要像精心设计的高级产品，不能有"AI 生成感"。

---

## 2. 核心原则（按重要性排序）

1. **质感第一。** 高清、有触感、有深度的真实材质（皮革感浮雕、叶脉、颗粒）。程序画出来的纹理一般显得假、平、糊，不要用。
2. **不要"AI 味"。** 大面积浅绿/米色、灰绿中性色、紫蓝渐变，都会被认为是机器做的、廉价的。
3. **品牌色要少量、深、有纹理。** 深色品牌色只放在色带上（页头、首屏、页尾）。大面积平涂的品牌色，不论深浅都难看。
4. **中性色必须是真中性。** 背景、卡片、线条、文字的灰色不带色相，绝不染成品牌色。
5. **但内容区也要有品牌色。** 完全中性会显得太克制、发黑。品牌色出现在"有意义"的元素上：主按钮、选中框、边界、标题、状态点。
6. **深色品牌色要能看出颜色。** 深绿必须一眼看出是绿，不能暗到像黑色。
7. **清晰优先于装饰。** 工具型界面（画布、图表、表单）先回答"这是什么、在哪里、有多少"。抢信息的装饰不要。
8. **结构清楚，层级严格。** 每个功能只有一个家，不重复出现。可点击的东西看起来就可点击。
9. **主题感要保留。** 项目有主题（例如植物），视觉就要带这个主题，不能做成任何产品都能套的通用模板。
10. **留呼吸感，页面要干净。** 宁可留白，也不要塞满。每屏只放必要的东西，元素之间有足够间距，让眼睛有地方休息。详见第 8.5 节。

---

## 3. 明确不要的东西

| 不要 | 原因（Yue 的反馈） |
| --- | --- |
| 紫色/蓝色渐变的"AI 产品"风格 | 千篇一律，像 AI 生成 |
| 照搬 Linear / Notion 的纯黑白 | 没有自己的性格 |
| 工业仪表风：等宽字体读数、细线、硬直角 | 冷、像机器，不舒服 |
| 大面积浅绿、米色、灰绿中性色 | "AI 做的"、钝、不酷 |
| 大面积深绿或中绿的界面（暗色主题） | 深、中、亮三档全部被否定："都很丑，甚至不如中性白" |
| 深色色带暗到发黑 | 失去颜色，看起来像黑色 |
| 程序生成的纹理（canvas 画的脊线、叶脉） | 假、平、糊 |
| 卡通感：饱和的土色、陶土色、亮色圆点 | 幼稚 |
| 景观设计式的渲染（叶片、果实、碎石路、阴影） | 装饰盖住了真正的信息 |
| 光秃秃的下划线文字链接当主要导航（"Back to gardens"） | 不容易发现，没有按钮的分量 |
| 同一个功能在两个地方出现（全局导航 + 子标签） | 用户分不清自己在哪 |
| 导航项没有视觉分量、没有分组 | 看起来不像可以点 |
| 导航文字太小 | 读起来费劲 |
| 荧光强调色到处用 | 荧光色是"科技感"的来源，用多了就廉价 |

## 4. 颜色体系

### 4.1 角色和比例

| 角色 | 用在哪 | 面积 |
| --- | --- | --- |
| 中性色（无色相） | 页面背景、卡片、线条、正文 | 绝大部分 |
| 深色品牌色 + 真实纹理 | 首屏、页尾、App 页头这些"色带" | 少量、成块 |
| 内容品牌色（深、实色） | 主按钮、选中框和控制点、边界、标题、已保存状态点 | 点缀 |
| 荧光强调色 | 官网的主行动按钮 + 一处标志性动效；App 里只用在"今天的照料进度条"（Care 色带、Gardens 的 Today 卡片，ADR-0080/0081） | 官网最多两处，App 只有这一种用途 |
| 语义色（错误、警告） | 只在需要时 | 极少 |

### 4.2 参考色值（植物主题版）

**中性色（完全无色相）**
- 页面 `#F4F4F3`，卡片表面 `#FFFFFF`，柔和底 `#F2F2F1`
- 线条 `#E3E3E1`
- 文字三级：`#18181A`（正文）、`#5F5F63`（次要）、`#8D8D91`（更弱、输入框边框）

**内容品牌色**
- 主色 `#1F4230`，悬停 `#285239`，标题 `#173322`
- Yue 要求"更深一点"后定下来的值。之前 `#2B5238` 偏浅。

**深色色带**
- App 页头 `#264A33`，上面叠一张灰度纹理照片（overlay 混合 75%），左边只加一点点渐变。
- 官网首屏底色约 `#14281D`，用着色器把照片亮度映射到三个固定深绿。
- 页尾纹理在映射前做 gamma 0.6 提亮，避免发黑。
- 规则：每条深色色带都要和首屏中间调一样"看得出是绿"。

**荧光强调色**
- `#D6FF5C`（青柠），上面的文字用很深的绿 `#0E1D14`。
- 发光阴影：`0 0 0 6px rgb(214 255 92 / 14%), 0 12px 34px -8px rgb(214 255 92 / 50%)`。

**语义色**
- 错误 `#B42318` / 底 `#FFF1F0`；警告 `#8A4B08` / 底 `#FFF7E8`。

### 4.3 颜色规则

- 中性色永远不染品牌色。
- 深色色带上的文字全用白色。不要用淡绿、灰绿文字配深绿（会有 AI 感）。
- 所有颜色写成 CSS token（`tokens.css`），组件里不写死色值。用测试检查对比度。
- 数据可视化里的颜色要有含义（例如按作物科着色，和轮作关联），不要随机分配鲜艳色。

## 5. 质感和纹理

- **用真实的高清照片，不要程序画。** 素材来源是 Pexels 等免费图库，记在 `CREDITS.md` 里。
- **照片用着色器重新调色，而不是直接放。** 做法是 WebGL2 片元着色器：
  - 把照片亮度映射到几个固定的品牌深色，所以不管用哪张照片，品牌色都一致。
  - 从模糊后的亮度算法线，得到浮雕感。
  - 一束柔光跟着鼠标移动；没有鼠标时慢慢绕圈。
- **叶脉/电路效果。** 用带通（两档模糊相减）提取叶脉，鼠标附近的叶脉亮成荧光色，像电路走线；最亮的点上放 SVG 节点。这个"叶脉 = 电路"的点子 Yue 很喜欢。
- **纹理也可以用在 App 页头**：灰度纹理照片叠在实色上（overlay 混合），低调但有质感。
- **一定要有兜底。** 没有 WebGL2、加载失败、或用户开启"减少动态效果"时，显示同一调色预渲染的静态图。离开视口就暂停动画。
- 素材体积要控制：灰度 WebP、2000px 宽，两张约 1.1 MB，在文字之后加载，不阻塞首屏。

---

## 6. 毛玻璃

Yue 喜欢毛玻璃，但要用在"浮在内容上"的元素上，并且背后要有东西可模糊。

**浅色玻璃（App 里浮在画布上的工具栏、缩放、图例、面板）**
- 白色 40% 透明，`backdrop-filter: blur(10px) saturate(1.5)`，白色细描边。
- 玻璃背后放一层淡淡的点阵，让模糊效果看得出来。
- 窄屏（< 900px）时取消浮动，回到正常排版。

**深色玻璃（官网首屏上的卡片和次要按钮）**
- 卡片：白色 8%，`blur(22px) saturate(1.1)`，圆角 24px，投影 `0 40px 80px -40px rgb(0 0 0 / 75%)`，顶部内高光 `inset 0 1px 0 rgb(255 255 255 / 14%)`。
- 次要按钮（ghost）：白色 7%，`blur(12px)`，悬停变 14%。

## 7. 字体

- **正文：Instrument Sans**，官网和 App 都用，保证两边是同一个品牌，并且 Windows 和 macOS 上看起来一样（不依赖系统字体）。
- **展示字体：Bricolage Grotesque**，只用在官网的大标题；App 里的例外只在深色色带上的大标题和大数字（Care 色带的 "4 things left today."、History 标题；Gardens 的 "Your gardens"、日期大数字、AI Garden Notes 标题，ADR-0080/0081）。它有性格，适合标题；用在小标签、按钮、数字上会累眼。
- 字体自托管（Next.js 用 `next/font`），运行时不请求 Google Fonts。
- 不用等宽字体做装饰性读数。

**字号和字距参考**
- 首屏大标题：`clamp(2.5rem, 6vw, 4.625rem)`，字重 500，行高 1，字距 `-0.035em`。
- 区块标题：`clamp(1.5rem, 2.6vw, 2rem)`，字重 500，行高 1.1，字距 `-0.02em`。
- 引导段落：17px，行高 1.55，最大宽度约 44ch。
- 正文/说明：16px，行高 1.55。
- 小标题（kicker）：12–13px，全大写，字距 `0.08–0.1em`，字重 600，用品牌色。
- App 导航：15.5px，字重 500，白色（约 92%），加一点点文字阴影；Logo 18px。
- 大标题用较轻的字重（500）和负字距，不用粗黑体。

## 8. 组件和细节

- **圆角：** 控件 8px，卡片 14px，大卡片 20px，玻璃卡片 24px；按钮和导航激活态用胶囊形（999px）。圆润但不幼稚。
- **主按钮：** 胶囊形实色。官网用荧光色；App 用内容品牌色。按下有轻微位移动效。
- **次要按钮：** 品牌色描边胶囊，悬停时填满品牌色、文字变白。
- **ghost 按钮：** 深色背景上的毛玻璃胶囊。
- **导航：** 激活项用更亮的胶囊底；导航分组之间用分隔线（例如核心模块 | 辅助工具）；全局快捷动作（例如"+ Note"）做成页头里的按钮。
- **返回和层级：** 用面包屑（Gardens › Backyard › Raised bed A）加一个真正的按钮（"All gardens"），不要只用一个下划线链接。
- **卡片：** 白底、浅灰细边框、不靠重阴影。
- **焦点状态：** 可见的 `focus-visible` 描边，颜色用品牌色；有"跳到内容"链接。
- **状态：** 加载、空状态、错误状态都要设计，不能留白。

## 8.5 呼吸感和干净

Yue 喜欢有呼吸感的页面：留白充足、内容不拥挤、一眼看清重点。

**留白**
- 留白是设计的一部分，不是浪费。不确定时，间距宁大勿小。
- 用统一的间距刻度（4 / 8 / 12 / 16 / 24 / 32 / 48px），不随手写零碎数值。
- 区块之间的间距明显大于区块内部的间距，靠间距分组，少靠线条和边框分组。
- 卡片内边距要宽松（大卡片 24–32px 以上）；按钮和输入框高度舒展，不挤。
- 页面两侧留足边距：手机 16–32px，平板 48px，桌面 64px；内容区有最大宽度（约 1440px），超宽屏不铺满。
- 正文行长控制在约 44–70 个字符宽，行高 1.5 以上。

**干净**
- 每屏一个主要任务、一个主按钮。次要操作降级成次要按钮或收进菜单。
- 去掉不必要的分隔线、边框、阴影、图标和装饰。能用间距和字号区分的，就不加线。
- 文字少而准：标题短，说明一两句；不堆砌解释性文字。
- 颜色种类少：大部分是中性灰，品牌色只点缀（见第 4 节）。
- 对齐整齐：用统一的网格和左对齐，元素边缘对得上。
- 信息分层展示：默认只显示常用内容，细节按需展开，不一次全摊开。
- 空状态也要干净：一句话说明 + 一个行动按钮，不放大段文字。

**注意**
- 干净不等于空洞。内容区仍然要有品牌色点缀和清晰的层级（第 2 节第 5 条：完全中性会显得太克制）。
- 工具型界面（画布、表单）在保证信息清楚的前提下留白；浮层玻璃面板要紧凑，不挡住内容。

## 9. 信息架构和导航

- **官网和 App 是两个独立的"框架"。** 各有自己的布局和页头，从不混用（参考 Notion / Linear）。官网可以有表现力，App 保持安静。
- 官网的任务：让第一次打开链接的人（例如面试官）马上知道产品是什么，再展示最强的一两个功能，一键进入 App（"Open app"按钮、首屏主按钮、每个功能的"Try it"）。
- 功能展示用动画卡片或短视频，基于真实界面截图，不嵌入可操作的完整 App。
- **App 层级严格：**
  - L1：全局模块，在页头。
  - L2：单个对象（例如一个花园），只做编辑。
  - L3：对象的局部（例如一个种植区），在同一画布上放大。
- 每个模块只有一个家。跨层跳转用"带筛选条件的链接"（例如 `/care?location=…`），不要重复做子标签。旧链接要重定向，不能失效。

---

## 10. 画布、图表、数据可视化

- 画法像"干净的公制规划图"，不是景观效果图。
- 底色接近白色，加浅色网格。
- 区域轮廓细：不同类型用边框样式区分（实色细框、虚线、圆形），不用大面积饱和色块。
- 填充颜色柔和，描边更深一档。
- 图形尺寸要有真实含义（例如植物圆圈直径 = 实际种植间距）。
- 每组元素都带简短标签（"Tomato ×2"），并配图例。
- 名字放在框的上方，不压在内容上。

---

## 11. 动效

- 动效要细腻、有目的：鼠标跟随的光、慢速绕圈、叶脉被点亮、分割线动画、当前步骤轻微脉动、按钮按下的小位移。
- 不做花哨的大动画。
- 尊重 `prefers-reduced-motion`：关掉动画，显示静态图。
- 离开视口暂停，不浪费性能。目标 60 fps。

---

## 12. 响应式和工程约束

- 在 1440、768、390px 宽度和 200% 缩放下都要好用，任何宽度都不能横向滚动。
- 浮动玻璃层在 900px 以下回到正常排版；手机上隐藏次要的页内导航。
- 设计 token 集中放在一个文件里；画布库（如 Konva）读不到 CSS 变量时，用一个 TS 文件镜像颜色。
- 只为视觉不引入新的组件库或第二套样式系统（例如 restyle 中途加 Tailwind/shadcn）。CSS Modules + token 足够。
- 字体自托管，第三方运行时依赖越少越好。WebGL 手写，必须有兜底。
- 用浏览器测试检查页面只用允许的颜色、对比度合格、关键流程截图。

---

## 13. 工作方式偏好（做视觉决定时）

- **用真实 HTML 原型做风格决定，不用色卡。** 平面色块看不出纹理和玻璃。
- **多轮迭代，每轮一个版本号。** 方向对了以后再调颜色、亮度、深浅。
- **给切换器对比。** 在同一个原型里放几个选项（例如"中性白 / 暖石灰 / 深绿夜间"、"深 / 中 / 亮"），让 Yue 直接对比。
- Yue 靠"感觉"判断：常见反馈是"AI 味""假""糊""太暗了""像黑色""太克制了""不够酷"。收到这类反馈时，先找出具体原因（纹理、色相、亮度、面积比例），再给修正方案。
- 方向确认（"方向对了"）不等于颜色确认，要分开问。
- 认可的方案要记成决策文档（ADR），写明被否定的选项和原因，避免下次重复踩坑。

## 14. 迁移到其他项目

不同主题时，换掉具体颜色和素材，保留以下结构：

1. 选一个和项目主题相关的**深色、偏灰的品牌色**（例如植物 → 深苔绿；海洋 → 深海蓝灰；咖啡 → 深烘焙棕）。确保它在色带上"看得出颜色"，不发黑。
2. 找一两张和主题相关的**真实高清纹理照片**，转灰度，用着色器映射到品牌深色，放在首屏和页尾。
3. 中性色照抄第 4.2 节的无色相灰色。
4. 内容品牌色 = 品牌色的更深、更实的版本，只用在有意义的元素上。
5. 选**一个**和品牌色对比强烈的荧光强调色，全站最多用两处。
6. 字体组合：一款干净的现代无衬线做正文（Instrument Sans），一款有性格的展示字体只做大标题（Bricolage Grotesque）。
7. 毛玻璃只用在浮层上，背后要有东西可模糊。
8. 先做 HTML 原型给 Yue 看，再写代码。

## 15. 交付前自查清单

- [ ] 中性色没有色相，没有被染成品牌色。
- [ ] 品牌色大面积只出现在有纹理的色带上；内容区的品牌色只在有意义的元素上。
- [ ] 深色色带看得出颜色，不像黑色。
- [ ] 荧光强调色不超过两处。
- [ ] 纹理是真实照片，不是程序生成；有静态图兜底。
- [ ] 正文字体统一、自托管；展示字体只在大标题。
- [ ] 导航项有分量，激活态清楚；返回是按钮不是光秃链接。
