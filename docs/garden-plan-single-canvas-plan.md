# Garden Plan：单画布与首次引导实施计划

- 日期：2026-11-12（America/Toronto）
- 状态：方向与分阶段计划已确认（[ADR-0072](decisions/0072-use-a-single-plan-canvas-with-guided-setup.md)）；第 7 节记录确认结果。G1、G2、G3、G4 已完成；下一步 G5。
- 依据：用户确认的可点原型（第 4 版）、Native Garden Planner 与 Sunplot 的对比分析、当前代码核查。

## 1. 目标

让第一次使用的人不看说明就能画完一个花园：定尺寸 → 放种植区 → 种植物 → 进入照料。

- 只有一张画布、一种比例尺。点一块地，画布在原地放大到这块地；植物直接点在图上。
- 点类型按钮就出现标准尺寸的形状，直接拖动、拉角改大小。
- 提醒不拦截：重叠、拥挤、植物在区域外只给提示。
- 新花园有四步进度条；走完消失，变回普通编辑器。
- 画完直接接上照料记录、Garden Note 和下季规划。

本计划替代 [frontend-ui-ux-redesign-plan.md](frontend-ui-ux-redesign-plan.md) 第 7 节与 R3 中与上述冲突的约定（第二张植物画布、桌面端 Move 模式、区域属性 Save）。R3 已完成的拖动预览、Escape 取消、坐标输入、焦点循环与草稿保护继续沿用或迁移，不重写。

## 2. 前置条件（G0，不写代码）

1. **当前分支 `care-note-paid-checks` 有大量未提交改动**：R0–R5 重设计、care-note 批量提取、ADR-0061～0071 等。新工作必须建立在这些改动之上（`GardenPlanOverview`、`PlantingAreaInspector`、`editor/` 都在其中）。由用户决定如何提交或拆分这些改动；在此之前不开始 G1。
2. 提交后从该基线建立专用分支，建议名 `garden-plan-single-canvas`，所有阶段在这个分支上逐个交付、逐个审阅。
3. 本计划与 ADR-0072 随 G0 一起提交（需用户授权）。

## 5. 各阶段细节

### G1 画布外观与文案

- **范围**：`GardenPlanOverview.tsx` 的区域绘制与标签位置（`areaLabelPosition`、`fitThumbnailLabels`），`canvas/Canvas.module.css`，区域属性表单与花园尺寸表单的标签，首页缩略图共用同一绘制。
- **做**：
  - 高床：浅色土 + 粗木框；地栽：深色土 + 虚线边；盆栽：圆形；温室：玻璃色 + 屋脊线。颜色集中在 `src/lib/planAppearance.ts` 一个模块（Konva 画布读不到 CSS 变量）。应用目前只有浅色主题；以后加深色主题时只改这一处。
  - 区域名放在框的上方，按框宽截断，完整名称保留为可访问文本；选中时尺寸显示在框下方。
  - 所有尺寸叫法统一为 Width（左右）和 Length（上下），修正区域表单中两者对调的问题。
- **不做**：交互改动、高度字段、数据字段改名。
- **验收**：在 Demo Garden 中，高床和地栽不靠文字也能分辨；任意区域的名字都不压在植物上；花园表单与区域表单的尺寸叫法一致，且输入 Width 改变的是左右方向。
- **测试**：标签位置纯函数的单元测试（框上方、截断、贴近花园上边缘时的处理）；表单标签与字段绑定的组件测试；更新受影响的现有断言。

### G2 原地放大进入种植区

- **范围**：`GardenPlanOverview.tsx` 取景逻辑、`gardenWorkspace.ts` 的 `gardenPlanViewport`、侧栏标题与返回控件、`?area=` 路由参数。
- **做**：
  - 点一块地（或在区域列表点它）→ 画布用约 0.4 秒动画放大到这块地的外接矩形（旋转后的四角），其他区域降低透明度；显示 "Whole garden" 返回。
  - Escape 和返回按钮回到整个花园并把焦点还给该区域的文字链接。
  - 打开带 `?area=` 的链接直接进入放大状态。
  - 用户开启“减少动态效果”时不播放动画，直接切换。
  - 取代 ADR-0054 的 Focus beds / Full garden 切换：整个花园视图仍然按区域收紧取景，放大视图对准单个区域。
- **不做**：在画布上编辑植物（G3）。
- **验收**：在 1440px 和 390px 下点任意区域都能放大并返回；旋转 30° 的区域放大后完整可见；刷新带 `?area=` 的页面仍在放大状态。
- **测试**：取景计算的单元测试（含旋转、贴边、极小区域）；路由参数组件测试；`responsive-canvas.spec.ts` 增加放大/返回旅程。

### G3 在主画布上种植物

> 实施说明（2026-11-12 确认）：中等宽度和手机上，弹窗和整页会挡住画布，所以种植控件改放在放大后的画布下方；区域属性点 "Edit area"（`&edit=area`）打开。宽屏侧栏不变。拥挤、出界、铺满等纯函数放在新文件 `src/lib/plantLayout.ts`，推荐间距在 `src/lib/plantSpacing.ts`（来源：Missouri Extension G6201）。

- **范围**：新建 `src/lib/planGeometry.ts`（平面 ↔ 区域局部坐标换算，含旋转）；`GardenPlanOverview.tsx` 植物层；`GrowingAreaLayoutEditor.tsx` 去掉 `MetricLayoutCanvas`，保留植物属性表单；`gardenWorkspace.ts` 的拥挤、出界、铺满等纯函数。
- **做**：
  - 放大状态下，侧栏显示植物选择；选中后指针处跟随一个间距圈，点在区域内放下一株，可连续放；Escape 停止放置。
  - 点已有植物选中它：拖动移动、删除；侧栏显示它的类型、品种、间距和 X/Y 坐标（键盘与非拖动的替代方式，满足 WCAG 拖动替代要求）。
  - "Fill" 按间距铺满当前区域，跳过已占位置，单次最多 80 株，完成后提示数量并可撤销（撤销在 G5 前用删除这批植物实现）。
  - 拥挤（两株距离小于平均间距的 85%）和出界只标记并在侧栏列出，不阻止保存。
  - 侧栏列出本区域的植物组（同种植物 × 数量），说明照料记录挂在这些组上；分组仍由现有 `linkCurrentLayoutPlants` 逻辑负责。
- **不做**：区域拖动方式的改变（G4）；撤销栈（G5）。
- **验收**：在旋转和未旋转的区域里都能点到哪种到哪；保存后刷新坐标不变；Fill 后数量正确且不覆盖已有植物；拥挤提醒出现但不阻止操作；原有植物属性编辑、复制、删除仍可用。
- **测试**：`planGeometry` 的往返换算测试（0°、30°、90°、180°）；拥挤/出界/铺满的单元测试；重写 `PlantingAreaInspector.test.tsx` 与 `AreaDraftProtection.test.tsx` 中依赖第二张画布的部分；`draft-protection.spec.ts`、`responsive-editor.spec.ts` 的植物拖动旅程改到主画布上。

### G4 直接摆放种植区

> 实施说明（2026-11-14 完成）：空位查找、默认名称、角把手尺寸计算和重叠判断在新文件 `src/lib/areaPlacement.ts`。鼠标在整园视图里可以直接拖任何区域，在放大视图里拖当前区域；变暗的邻居不动。花园比标准尺寸小时，新区域缩小到花园大小并在提示里说明；花园放满时居中放下并提示重叠。类型名统一为 Raised bed、In-ground bed、Container、Greenhouse。

- **范围**：`GardenPlanOverview.tsx` 拖动与缩放把手；新增区域流程（替换 `Add planting area` 表单）；`gardenWorkspace.ts` 的空位查找纯函数；`WorkspaceHome.tsx` 的 "Layout needs setup" 文案。
- **做**：
  - 侧栏四个类型按钮：Raised bed 1.2 × 2.4 m、In-ground bed 2 × 3 m、Container 0.6 × 0.6 m、Greenhouse 2.5 × 3 m。点一下在第一个空位出现（默认名如 "Raised bed 2"），并自动选中。
  - 鼠标/触控笔：选中后直接拖动主体移动、拖右下角把手改尺寸；保留 6px 阈值、吸附预览、原位置虚线和 Escape 取消（ADR-0070）。
  - 触屏：保留显式 Move 模式，未开启时画布可正常滚动页面；只在粗指针设备上显示 Move 按钮。
  - 无尺寸的旧区域列在 "Needs a size" 下，"Place on plan" 用该类型默认尺寸放到空位。
  - 重叠时两个区域都显示警告描边，侧栏说明，不阻止。
- **不做**：自由多边形、图层、硬景观。
- **验收**：鼠标用户不开任何模式就能新增、移动、缩放区域；手机上滑动画布仍能滚动页面，开启 Move 后能移动；旧的无尺寸区域点一次出现在图上。
- **测试**：空位查找单元测试（满、贴边、花园小于默认尺寸）；指针类型分支的组件测试；`garden-flow.spec.ts` 改用新增按钮；手机触摸旅程沿用 R5 的 touch 测试并补 Move 场景。

### G5 自动保存与撤销

- **范围**：新增 `src/hooks/usePlanHistory.ts`；`useWorkspaceSync.ts` 冲突事件通知；区域属性表单（去掉 Save）；`areaEditorDrafts.ts`；页头撤销/重做按钮与快捷键。
- **做**：
  - 每次拖动结束、放置、删除、铺满、属性提交都是一次变更，记录变更前的花园快照（仅当前花园的 `plan`、`growingAreas`、`plantings`），上限 100 步。
  - 撤销/重做把快照作为新的正向修改写入，不回退服务器 revision。
  - 切换花园、刷新、收到 409 或远端更新时清空历史，并提示“撤销历史已清空”。
  - 区域名称、类型、尺寸、坐标、旋转在失焦或回车时校验并提交；校验失败保留输入并显示错误，不提交。
  - 植物属性表单同样改为提交即保存；ADR-0062 的草稿保护只在输入未提交时生效。
  - Ctrl/⌘ Z、Shift+Ctrl/⌘ Z；焦点在输入框时交给浏览器自己的撤销。
  - 此阶段落地时把 ADR-0052、0062 标记为对 Garden Plan 部分修订。
- **不做**：跨标签页或持久化的历史。
- **验收**：误拖一个区域后按撤销能回到原位并成功同步；连续撤销/重做后刷新，页面与最后一次操作一致；冲突发生后撤销按钮变为不可用并有说明；Garden Plan 不再出现区域 Save 按钮。
- **测试**：`usePlanHistory` 单元测试（上限、清空条件、重做在新修改后失效）；与同步串行写入的集成测试（快速连续撤销只产生有序写入）；`sync-recovery.spec.ts` 增加冲突后历史清空。

### G6 首次引导

- **范围**：`GardenWorkspace.tsx` 新建与 setup 流程；新增 `src/components/editor/SetupProgress.tsx`；Ready 摘要面板；花园尺寸步骤（预设和可拖的边界角）。
- **做**：
  - Add garden 只问名字 → 进入 Garden Plan，上方显示进度条：Garden size、Planting areas、Plants、Ready。
  - 进度条样式按原型：Step N of 4、已完成打勾、当前步骤放大并有呼吸光圈、未开始虚线；进度线随步骤滑动；减少动态效果时关闭动画。
  - 已完成的步骤可以点回去；未到的步骤不可点。每步侧栏只显示该步需要的控件，画布始终是同一张。
  - Garden size：宽、长输入，常见尺寸（3 × 2、6 × 4、12 × 8 m），可拖右下角；不能小于已有区域的范围。
  - Plants 步骤允许 "Skip plants for now"。
  - Ready：区域数、植物数、植物组数；三个入口：记录第一次浇水（Care 并预选此花园）、写 Garden Note（打开首页同一弹窗会话）、规划下一季（Next Season 此花园）。
  - 离开 Ready 后进度条消失；没有区域的花园显示 "Start guided setup"。
  - 引导状态沿用会话级 `setup:garden` 草稿，不新增存储字段。
- **不做**：示例模板库、地图定位、日照分析。
- **验收**：一个新用户从 Add garden 到 Ready 不需要其他页面说明；中途刷新回到同一步；从 Ready 的三个入口都进入正确的花园上下文。
- **测试**：进度条状态与可点性组件测试；新建流程组件测试；新增 `e2e/guided-setup.spec.ts`（1440px 与 390px 各一遍完整引导）。

- 只交付本阶段的用户能力，不顺手改其他页面。

## 7. 已确认的决定（2026-11-12）

用户确认以下四点均按建议执行：

1. **触屏的移动方式**：手机保留显式 Move 模式，未开启时画布区域可以滚动页面；鼠标和触控笔直接拖动（G4）。
2. **默认植物间距**：给常见植物加默认间距建议，用户仍可修改；每个数值在代码注释或数据表中标明来源（G3）。
3. **去掉 Save 按钮**：放进本轮，作为 G5 单独交付和验收；落地时把 ADR-0052、0062 标记为对 Garden Plan 部分修订。
4. **当前未提交的改动**：先按主题整理成几个提交，用户过目并授权后再提交（G0）。
