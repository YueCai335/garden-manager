# Garden Manager：前端 UI / UX 重设计执行方案

日期：2026-11-12（America/Toronto）  
状态：用户已确认产品层级与首页笔记弹窗；以下视觉规格、批次与技术落实方案待审阅。本文不代表已完成视觉验收。

## 1. 目标、依据与范围

把产品整理成以花园地图为中心、可直接操作、状态清楚的园艺工作台。
专业感由信息层级、对齐与间距、控件一致性、真实数据呈现、操作反馈和错误恢复共同构成。

用户已确认：

- Overview 首先展示每个 Garden 的缩略图，能辨认相对布局与当前种植内容。
- 首页有明显的 Garden Note 按钮，打开弹窗；写笔记、跨花园逐条审核、保存都可以在首页完成。
- 近期待办使用紧凑窗口，区分 Overdue、Today、Upcoming。
- 点击 Garden 进入地图；点击菜床／种植区编辑属性、种植内容和间距；可以在地图拖动位置。
- Plant Doctor 与 Next Season 在全局导航有明确入口。

本方案细化并替代旧方案第 1–3 节、T04 与 T05 中冲突的展示约定，特别是“首页大块 AI 输入在花园之前”。
T01–T08 已完成的数据保护、路由、同步、批量提取与事务保存继续复用。
旧测试通过数证明相应行为的回归结果，不等于新设计已被用户接受或完成浏览器验收。

不自动提交、推送或部署；不调用付费模型；不开放公开演示限额；不清空用户数据。
本轮先交付方案。后续实施按批次推进，不一次铺开所有页面。

## 2. 审核方法与交付标准

### 2.1 四层审核

| 审核层 | 方法 | 本项目要回答的问题 |
| --- | --- | --- |
| 任务与信息架构 | 按用户真实任务梳理入口、对象与返回路径 | 打开首页能否直接找到花园、记录入口和今天要做的事？ |
| 交互可用性 | Nielsen 启发式审核与逐步任务走查 | 能否看懂哪里可点、当前选中谁、操作是否成功、出错如何恢复？ |
| 视觉与控件 | 组件清单、状态矩阵、真实内容高保真样板 | 同类操作是否一致，是否有明确主次，长内容和空数据是否仍整齐？ |
| 可访问性与适配 | WCAG 2.2 AA 目标、APG 弹窗模式、键盘与真实浏览器测试 | 不用鼠标拖动能否完成任务？焦点、对比度、触控与窄屏是否可用？ |

遵循标准是设计与测试目标，不能未经审核宣称 WCAG 合规认证。
本项目主要控件采用至少 44×44 CSS px 的触控区域；这是项目设计目标，WCAG 2.2 AA 的目标尺寸最低要求是 24×24，另有间距等例外。

### 2.2 问题分级

- S0：数据丢失、错误花园写入、重复记录；立即阻断交付。
- S1：主要任务走不通、无法恢复、键盘无法完成；完成对应批次前修复。
- S2：布局混乱、主次不清、同类控件不一致；新样板页面不遗留。
- S3：细微间距、装饰与非关键动效；可以集中收尾。

每条问题记录页面、触发条件、截图或代码证据、用户影响、修复方案与验证结果。
目前未完成新一轮真实浏览器走查，不虚构可用性得分、完成时间或用户测试结论。

## 3. 当前代码已核实的问题

| 证据 | 对体验的影响 | 处理 |
| --- | --- | --- |
| `WorkspaceHome.tsx` 将笔记与待办放在花园网格之前 | 首页先看到表单，花园成为次要内容 | 花园网格优先，笔记改为按钮与弹窗 |
| 首页卡片只有花园名、区域数；compact 画布隐藏植物文字 | 颜色圆点不足以说明种了什么 | 增加真实作物摘要及可辨认区域标签 |
| `AppShell.tsx` 全局导航没有 Next Season；首页下方另有工具链接 | 入口重复且重要规划功能不稳定 | 统一导航，删除首页重复工具区 |
| 导航链接未取消默认下划线 | 导航、正文链接与按钮视觉语言混杂 | 使用统一导航项样式与当前页状态 |
| `SyncStatus` 在页头直接铺开长说明和错误 | 页头随状态突然增高，正文被下推 | 常态短状态，异常独立消息条与恢复区 |
| `controls.css` 已有部分 hover，缺少完整 pressed 状态；调用点同时使用组件和裸按钮 | 不是完全没有交互，而是反馈覆盖不完整、难以感知 | 统一控件和状态，逐页迁移 |
| 多组旧 class 别名与 legacy 样式并存 | 改一个页面难以保证其他页面一致 | 迁移一个模块验收一个模块，按引用移除废弃规则 |
| 工作区 404 被显示为泛化连接错误 | 用户只能反复 Retry | 明确区分不存在与暂时失败，设计安全恢复路径 |

现有画布已绘制植物配置、按比例定位并支持移动模式；本轮优先改善可读性、发现性与操作反馈，避免重写几何算法。

## 4. 信息架构与全局外壳

建议桌面导航顺序：Overview / Care / Next Season / Plant Doctor / Plant Guide。
Garden Note 是醒目的全局操作按钮，首页同样可直接启动；它的视觉身份不与页面导航混为一谈。
Care 和 Plant Guide 保留，不因本轮用户未重复提及而删除。

- `/`：花园总览。
- `/gardens/[id]/plan`：特定花园地图与编辑器，区域选择沿用现有深链接。
- `/care`：跨花园任务／历史；仍可按地点筛选。
- `/season`：下一季规划总入口，保留具体花园子路由。
- `/doctor`、`/guide`：诊断、查询；明确展示选中对象及范围。
- `/notes`：保留可直接访问的兼容页面，与弹窗共享同一会话和审核组件；首页按钮不跳转该页。

桌面页头目标高度约 64–72px。首页页头保留品牌、导航和短同步状态，笔记入口位于 Care Tasks 上方。
导航当前项用底色／标记与字重表达，并保留 `aria-current`，不依赖颜色一种信号。
空间不足时折叠菜单，不把导航挤成两三行。手机保留可见的记录入口和菜单按钮。
页面只保留一处主标题。使用简短面包屑表达“花园 / 前院”，避免重复标题与大段引导文字。

同步状态常态显示“已保存／保存中”；说明可展开。错误在导航下方显示独立消息条，提供可执行操作。
路由焦点移动继续保留，但普通标题不呈现像输入框一样的常驻边框；键盘交互控件仍有明确焦点环。

## 5. 首页：花园是视觉主体

### 5.1 桌面布局

内容最大宽度以 1440px 为起点，两侧留 24–40px，依据实际截图调整。
简短页头显示 Overview。花园区标题显示花园数量和 Add garden 入口。

主体左侧为花园网格，右侧为约 300px 的操作与待办栏。Record Garden Note 使用整栏宽的大按钮，紧贴 Care Tasks 上方。
网格根据可用宽度选择 1／2／3 列。在 1440px 桌面视口使用三列，让六个花园占两行。
不使用轮播或默认折叠花园，不要求先选一个 Garden 才能看到其余 Garden。
“每个花园都可一眼找到”解释为连续可浏览网格；花园数量多时正常纵向滚动，不承诺任意数量同时塞进一个屏幕。

每张卡片：

1. 桌面约 148px、手机约 112px 高的俯视缩略图。取景围绕有尺寸的菜床收紧，保留真实区域形状、位置、旋转与种植配置。
2. 花园名称；区域数量；当前作物名称摘要，最多约三项，余量以“另外 N 种”表示。
3. 简洁的进入提示。整张卡片是一个链接，不嵌套第二个按钮或拖动交互。

绘制规则：同一张图保持米制等比例；每个花园独立适配卡片，不暗示不同卡片比例相同。
未设置尺寸／位置的区域要显示“待设置”摘要，不能从卡片里悄悄消失。
作物摘要以当前种植记录为依据，空间符号以已有布局配置为依据；两者不一致时不得把布局草图冒充实际种植。
缺少真实位置时只显示名称摘要，不编造植物坐标。未来季节数据不混入当前缩略图。
卡片外提供文字信息，避免读屏用户只能面对无语义 Canvas。

### 5.2 近期待办

- 一张紧凑面板，分 Overdue / Today / Upcoming，Upcoming 明确为未来七天。
- 显示各组总数及最多五条摘要，按逾期、今天、临近日期排序；更多内容进入 Care。
- 每条显示动作、花园／区域、到期日，长名称可换行；不靠红点猜状态。
- 默认不在首页放复杂任务编辑表单。进入 Care 后可完成或编辑。
- 无任务时显示一行轻量空状态与 Add task，面板不膨胀。

### 5.3 手机与空状态

手机把记录按钮和待办放在花园网格前面。花园区宽度达到 340px 时排两列，更窄时排一列。
空花园用明确的 Create garden 主行动和轻量演示入口，不用无数据的大地图占位。
初次加载使用接近实际卡片尺寸的骨架屏；不能先闪现“没有花园”再变成有数据。

## 6. Garden Note：原地完成的弹窗

桌面弹窗宽度以 880–960px 为起点、高度不超过约 90dvh；手机使用全屏对话框。
使用一个内容滚动区，顶部标题／关闭与底部主要操作稳定可见，输入框和错误不得被遮挡。

| 状态 | 内容和操作 |
| --- | --- |
| 记录 | 文本输入、跨花园示例、字符数；“生成待审核记录”为主，“手动添加”为次 |
| 生成中 | 按钮显示“正在整理…”并禁止重复请求；输入与已有草稿保留 |
| 审核 | 原文、N 条／M 个花园摘要、逐条勾选与修改；主要操作为“保存选中的 N 条” |
| 保存中／失败 | 区分已加入工作区和已同步；弹窗内可访问同一同步重试／冲突操作，避免被背景遮住 |
| 完成 | 明确保存数量，提供“完成并关闭”“再记一条”“查看记录”；未选行仍可继续审核 |

逐条卡片先显示动作、日期、地点和是否包含；必要字段始终易找到。
肥料详情等低频字段渐进展开。错误字段自动展开并定位，不能把错误藏在折叠区。
六条记录通过同一个内容区滚动审核，不使用六张各自滚动的小窗口。

关闭按钮或 Escape 只收起窗口，草稿保留在当前标签页；重新打开回到原状态。
有草稿时首页按钮显示“继续笔记 · N 条”。彻底清空草稿才需要明确确认。
点击遮罩不关闭，防止误触；刷新／关闭浏览器可能丢失未提交草稿，沿用离开提醒。
保存过程中可收起窗口，同步继续；重新打开显示真实保存状态，不重新应用记录。

弹窗使用正确标题、`dialog` / `aria-modal`、背景不可交互、焦点限制与关闭后的焦点恢复。
已有重生成／删除确认必须与焦点、滚动锁协调；嵌套确认只保留最上层可交互。
复用 `useCareNoteBatchSession` 和原子保存，不复制一套弹窗专属业务状态。
公共模式仍使用既有受限单事件／手动路径，弹窗入口不得绕过 capability 检查。

## 7. 花园与种植区：地图和属性联动

### 7.1 Garden 页面

桌面采用大地图加右侧约 320–380px 的属性面板。地图是主工作区，属性表单不占首屏大半。
顶部工具条包含 Add planting area、视图适配、缩放与移动模式状态；图标配文字或可靠的可访问名称。
无选中区域时侧面板显示简短花园摘要；选中时显示区域名与属性。
区域列表作为地图的键盘替代入口；地图、列表、面板使用相同选中状态。

区域属性分两部分：“尺寸与位置”“种植内容”。
名称、类型、平面长宽、坐标、旋转使用明确单位；进阶字段收起。
布局保存不清空另一个区域或植物尚未提交的草稿。

### 7.2 拖动与点击

桌面点击选择；超过小位移阈值才进入拖动，拖动结束不触发额外“点击打开”。
拖动时显示 grab/grabbing、选中边框、原位置／目标预览与网格吸附，松开后统一提交一次位置变化。
视图缩放不改变真实米制坐标；遵守现有边界／重叠规则，不借视觉改版偷偷改变业务限制。
提供坐标输入和方向移动按钮；不把拖动作为唯一方法。
触屏先点选，再通过明确的 Move 模式拖动，避免页面滚动误移动菜床。
取消未结束拖动恢复原位置；Undo/Redo 若扩展到持久化历史，应另列功能，不能用未实现的按钮装饰工具条。

### 7.3 种植内容与间距

查看植物名、品种与已有数量；添加／编辑植物时展示对应位置与间距预览。
当前模型的布局占位尺寸若代表间距，须使用一致说明；不能画成实际冠幅并让用户误解。
字段标注 m 或 cm，显示单位转换但只保存一种规范单位。
修改种植与未来轮作分别在当前花园与 Next Season 中完成。

**高度字段需单独核实并落实：** 当前主要二维布局字段是 widthMeters / depthMeters，后者是平面另一边，不是菜床高度。
实施阶段核对种植区 schema；如无持久化高度字段，单独增加可选 heightMeters、数据库迁移、API 和旧数据兼容测试。
仅用于适用区域类型（如高床）的属性显示，不把未知旧值填成 0，也不引入三维编辑器或光照模拟。

### 7.4 响应式编辑

宽屏地图／面板并列；中屏使用可调整展开的面板，保证地图有足够空间；手机用可收起底部面板。
手机默认摘要态仍能看到所选区域，进入完整表单后支持明确返回地图；不同时堆叠三个抽屉。
软键盘、底部安全区、200% 缩放下保存与取消仍可触达。

## 8. 统一视觉系统与操作语言

建议方向：克制的园艺工作台。沿用低饱和森林绿，以暖灰白背景、白色表面和细边框区分层级。
花园图是主要视觉内容，不使用装饰性照片替代真实布局，不用大渐变横幅占首屏。

| 项目 | 第一轮样板规格，需实测后定稿 |
| --- | --- |
| 颜色 | 现有深绿／白／灰绿作为基础；成功、警告、错误使用独立语义 token |
| 字体 | 现有系统字体，正文 16px，辅助文字 14px，页标题约 28–32px，区块标题 20–24px |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48；字段 8–12、卡片内边距 20–24、主要区块 24–32 |
| 圆角 | 控件约 8px、卡片 12px、弹窗 16px；同类统一 |
| 表面 | 普通卡片细边框，弹窗适量阴影；不用每块内容都套多层卡片 |
| 图标 | 统一线条与尺寸；关键按钮保留文字；不混用 emoji 与不同图标风格 |
| 动效 | hover/pressed 约 120–160ms，弹窗约 180–220ms；减少动态偏好下禁用非必要动画 |

颜色和字号先做组件样板，验证正文对比度至少 4.5:1、大号文字至少 3:1，以及适用控件边界／图形的 3:1 要求。
不能只凭颜色代码或肉眼宣称达标。阴影、动效和颜色均不替代文字状态。

### 8.1 控件用途

| 类型 | 外观与用途 | 示例 |
| --- | --- | --- |
| 主按钮 | 实心品牌色；同一操作组通常一个主行动 | Record Garden Note、Save selected records |
| 次按钮 | 清晰描边、稳定点击区域 | Add garden、Cancel、Add record |
| 轻量按钮 | 有完整命中区域，静态无下划线，悬停有底色 | 展开详情、辅助编辑 |
| 危险操作 | 有明确删除文案，红色用于删除确认与风险提示 | Delete planting area |
| 导航项 | 统一页签／导航样式，当前项可辨认，无正文式下划线 | Overview、Next Season |
| 正文链接 | 用于说明中的目的地或资料引用，保留下划线 | 知识来源、相关帮助 |

跳转仍使用语义链接，执行动作仍使用 button；跳转入口可以呈按钮外观。
统一的是用途与视觉层级，不能把所有链接机械改成同样的实心按钮。

### 8.2 必备状态矩阵

| 状态 | 必须看见／发生的变化 |
| --- | --- |
| Default | 有明确边界、文字、可点击区域 |
| Hover | 底色或边框变化；卡片轻微强调，不引发布局跳动 |
| Pressed | 即时更深底色／内阴影；可选 1px 下压，禁用时不响应 |
| Focus-visible | 清楚的焦点环，和选中态可区分；不被固定栏遮住 |
| Selected | 导航、区域、筛选保持选中标记，并正确提供 aria 状态 |
| Loading | 稳定宽度、具体进行中文案、禁止重复提交；不只显示转圈 |
| Disabled | 视觉弱化、不可触发，必要时旁边解释启用条件 |
| Success / Error | 局部文字反馈；错误指出字段并保留输入；异步结果能被读屏获知 |

## 9. 其余页面按统一模板整理

- Care：标题、Tasks / History 切换、地点筛选、列表；过期／今天／即将到期分组，主操作明确，详情渐进展开。
- Next Season：导航直接进入；年份与花园范围置顶；区域规划卡片为主，轮作依据与 AI 分配建议作为展开内容；显示当前与未来的边界。
- Plant Doctor：对象 → 照片／描述 → 结果／审核，分组清楚；不会提交时自动调用 AI。
- Plant Guide：问题输入与回答主次明确；引用使用规范正文链接，不把每个来源都做成大按钮。
- 新建花园、空状态、无结果、加载、失败、缺失对象、确认弹窗使用同一套表面、排版和反馈规则。

工作区 404 必须单独处理：解释当前服务找不到该编号，保留原引用与浏览器副本；如有副本可先导出，再经明确操作恢复到新工作区。
没有可用副本时提供安全的新建入口，不能宣称恢复旧数据；网络错误／500 不能自动走重建流程。
此恢复逻辑与现有数据保护测试一起验收，不为美化页面而自动清空 localStorage。

## 10. 分批实施与文件范围

| 批次 | 工作与交付 | 主要涉及文件 | 完成门槛 |
| --- | --- | --- | --- |
| R0 审核与样板定义 | 记录当前问题、真实数据场景、布局与控件状态稿；确认新方向的 ADR | 本方案、决策记录、执行记录 | 范围清楚，无数据／业务暗改 |
| R1 控件与首页样板 | 页头导航、同步短状态、按钮状态、花园卡片与小待办面板；笔记按钮接已有会话入口 | tokens / controls / Button、AppShell、SyncStatus、WorkspaceHome、缩略图 | 真实 390/1440px 截图；用户认可首页方向后推广 |
| R2 首页笔记弹窗 | 原地输入、审核、保存、保留草稿、关闭恢复、弹窗内同步恢复 | notes 组件、WorkspaceProvider、批量 hook、对话框基础组件 | 键盘／焦点／6 条／失败重试均可用；不改原子保存 |
| R3 花园编辑器 | 地图／面板联动、拖动反馈、植物与间距编辑、手机面板；高度字段单列子任务 | GardenPlanOverview、PlantingAreaInspector、GrowingAreaLayoutEditor、editor CSS；必要 schema / migration | 地图真实可操作，单位正确，草稿不丢，拖动有替代方式 |
| R4 全站一致化与恢复 | Care、Season、Doctor、Guide、新建和错误页；修复工作区 404 死路 | 对应页面模块、useWorkspaceSync、API 错误处理 | 同类操作一致；主要流程无 S0/S1 问题 |
| R5 最终视觉与交互验收 | 多视口、多数据量、键盘、触控、截图复核；按引用清理旧样式 | e2e、测试、进度文档、废弃样式 | 验收矩阵逐项给出证据，不以脚本存在代替通过 |

R1 的按钮若 R2 尚未完成，应暂时复用已有可用审核入口并明确标为过渡；不得把路由跳转说成最终弹窗已完成。
每批只交付一个可审阅的完整范围，记录已完成、未完成、测试与下一步，便于中断后继续。
R1 是视觉方向检查点，避免首页风格尚未认可就改完所有页面。
执行顺序可在 R1 前先修阻断本地体验的 404 恢复，但独立测试与记录，不混入视觉是否通过的判断。

技术策略：沿用 React / Next.js / CSS Modules / 语义 tokens / Konva 和已有状态管理。
先迁移现有 Button/ButtonLink 与表单组件，禁止新建第二套同义按钮或在所有页面追加覆盖 CSS。
图标先复用已有资源；需要新增组件／图标依赖时，明确用途和范围后再决定，不为了“专业感”整站换框架。
保留原始未提交改动，每批查看 scoped diff；不删除历史代码前尚在使用的 class。

## 11. 验收矩阵：设计通过与技术通过分别记录

### 必测场景

- 视口：390×844、768×1024、1024×768、1440×900；另测 320px 回流和 200% 缩放。
- 数据：0／1／3／8 个花园，长中文／英文名称，0／多种植物，缺少布局，长任务名。
- 笔记：1／6 条、跨花园、缺失日期、取消勾选、手动添加、替换确认、关闭重开、软键盘遮挡。
- 编辑：单击选择与拖动区分、拖动结束位置、坐标调整、单位转换、保存／取消、切换对象保留草稿。
- 失败：工作区 404、网络中断、409、服务端保存成功但响应丢失；全程禁止重复创建和静默丢弃。
- 键盘：导航、进入花园、选择区域、编辑、打开／关闭弹窗、定位错误、完成保存。

### 设计完成门槛

1. 首页首屏能辨认花园与记录入口，主体不被大表单／大提示占据；桌面待办保持紧凑。
2. 常见任务中每个操作组的主行动清晰，同类控件外观与状态一致。
3. 地图／面板／列表的选中对象一致；内容溢出、遮挡、跳动问题已解决。
4. 每个可交互控件的 default/hover/pressed/focus/loading/disabled 适用状态有实测证据。
5. 用户看过首页和编辑器实际截图与操作效果，并确认方向；不能仅凭设计者自评结束。

### 技术完成门槛

- 运行相关单元／集成测试、typecheck、lint、构建、diff 检查；有新增逻辑时补有意义的回归测试。
- 真正执行浏览器旅程并留截图与失败记录；当前浏览器权限限制未解除时，明确标注待验收，不能以静态检查替代。
- 本地开发服务运行时，构建使用配置允许的独立输出目录或先协调停止服务，避免覆盖开发产物。
- 不用截图快照代替业务断言；不把 UI mock 的成功当作真实模型提取质量。
- 新 UI 验收后再接续旧计划的真实模型评估与 PostgreSQL 专项测试，保留原有待办。
